# 踩坑指南｜从 W1–W51 到公开模板

原有七行摘要在此扩为可定位、修复和验收的记录。依据历史 W1–W51 复盘、W48 制票规范、W49–W51 导出/收藏修复、v13 读桥说明，以及公开版声音、延迟、书写和视频修复整理。历史记录不冒充本轮新测试；仅从源码发现的接入风险单独标明。

## 视觉与声音

### 01｜把严格参考当成再设计

- **现象与依据：**W24–W29 的机身、金属件和父子容器曾反复返工；已明确严格还原，后续仍改变位置和比例。
- **原因：**未先测量几何，把结构和表面质感混在一起修改。
- **操作：**锁定已确认版本，记录目标容器位置、宽高、边距、层级及相对关系；同尺度对照，先修父子结构，再修纹理。W32 音效、W38/W41 布局和现有邮票列入保留项。
- **验收：**比较前后截图和 DOM 尺寸；目标差异缩小，保留区无意外变化。继承现有布局，不等于以后换皮肤无需重验。

### 02｜公开机器换成另一套声音

- **现象与依据：**公开版曾出现音效与原私人机不一致的反馈。
- **原因：**保留交互名称，却未完整迁移原采样、参数和 V3 出票程序。
- **操作：**从批准的 W32 原机提取八个短采样；保留原音调、摩擦、到达铃时序与翻纸加速/音高设置，不用“相似”合成声替换。
- **验收：**[sources.json](../template/assets/sfx/sources.json) 比对大小和 SHA-256，[声音检查](../tests/audio-parity.test.cjs) 核对程序与参数，再实际试听。哈希证明文件相同，不能证明听感相同；最早录音来源仍需另查。

### 03｜动作发生了，声音晚到

- **现象与依据：**公开版曾被反馈点击与声音有延迟。
- **已定位因素：**交互时才加载/解码，首个手势时音频通道未唤醒；实际设备还可能增加输出延迟。
- **操作：**短声提前加载解码，复用 AudioContext，在手势内先唤醒并播放，再渲染和存储；保留翻纸原播放方式。首次播放若已过期，加载后不突然补响。
- **验收：**检查首次、连续点击和静音切换，以及手机实际扬声器。回归覆盖准备、调度和过期请求，不能将它写成实测“零延迟”。

### 04｜背面静态文字被当成写字动画

- **现象与依据：**公开版曾遗漏写字层；PNG 有完整正文不等于逐字显示。
- **操作：**完整 PNG 作为纸面与下载成品，用可取消文字层重建阅读；保持 770ms 等待、2180ms 第一段、430ms 间隔、2060ms 第二段，最后落款。文字与钢笔声使用相同阶段回调。
- **中断：**翻回、合上、换信取消当前书写；静音只停止声音，文字继续。上一封回调不能写进下一封。
- **验收：**[书写检查](../tests/writer.test.cjs) 覆盖时序、静音和取消；再观察实际逐字效果。手机真机体验仍单列，存图不保存写到一半的状态。

## 画芯与导出

### 05｜整票乱码、建筑变形，甚至变成流程海报

- **现象与依据：**W42–W48 多次出现含字整票、图框漂移，概念展示与转换成品混淆。
- **原因：**把插画和精确排版交给同一生成任务；风格参考的物体还可能污染新场景。
- **操作：**模型只画无字画芯，程序写字和框纸。照片负责构图事实，风格参考只负责刻线、油墨与色彩；自主模式先核实事实。主体错只重做画芯，再由 Skill 自行套版并交付完整正反面，不让用户再发下一步指令。
- **验收：**原图、画芯、成品并排核对物体数量、建筑/窗棂轮廓、光线和焦点；检查无字无框。旧画芯跑通脚本，只证明套版兼容，不能证明本轮新生图成功。

### 06｜版本参数互相打架

- **现象与依据：**W42 测量初稿、W43 字体/简称草案、W47 固定像素和 W48 双模式容易混用。
- **操作：**从 [SKILL.md](../skills/yomemado-stamp-maker/SKILL.md) 进入现行规则和实际程序，历史参数只作解释；区分已确认、测试和提案。
- **验收：**同一输入重复套版，固定区和 Alpha 不变，文档参数对应实际脚本。例如不能用早期底部 45px 草案覆盖当前公共脚本的 49px、基线 931/976。

### 07｜地名挤不下，缩字或并成单行

- **现象与依据：**底部标题过长曾导致字级变化和单行，破坏固定母版。
- **操作：**事实全称与印刷短名分开，`footerShortLines` 恰好两个非空字符串；固定字级、字距和基线，超宽明确失败。先找准确短名，不能杜撰第二个词、自动缩字或挤框。
- **验收：**用长标题触发拒绝，再以合理两行通过。当前留园印刷 LIU / YUAN，事实仍为 The Lingering Garden，短名不能覆盖地图和藏信全称。

### 08｜RGBA 也可能有黑色齿孔

- **现象与依据：**历史测试有烘焙背景、黑边和正反尺寸不同。
- **原因：**RGBA 只说明模式，不保证蒙版正确；透明像素颜色污染或两套 Alpha 都可能出问题。
- **操作：**两面均 736×1040，继承同一母版 Alpha；纸内米白、外部与凹口透明，不先合成预览底色。
- **验收：**实际运行 `check_stamp.py`，核对尺寸、Alpha、外角与透明值，再叠白、黑、棋盘格检查全部边缘。当前检查器不识别图像语义；四角透明不证明每个齿孔正确，还要对照母版和实际边缘。

### 09｜CSS 字体对了，PNG 还是旧字或方框

- **现象与依据：**W49–W50 曾因字体回退及两路渲染造成页面/导出不同。
- **操作：**区分 CSS 字体与烘进 PNG 的像素。改 `fontFamily` 不重画图片；修改字形或内容后，指定可用 CJK 字体重新导出，同时替换页面数据。下载得到字体不等于可以随包再分发。
- **验收：**查看实际 PNG 的中文、日期和落款。公共网页允许宋体回退，不声称各设备字形逐像素一致；固定导出须明确字体与渲染环境。

### 10｜页面正常，下载错图、半成品或挤掉落款

- **现象与依据：**W49–W51 曾有背面显示/下载不同源、正文过长、落款挤压和双面尺寸不一。
- **操作：**页面与 ZIP 使用同一对完整 PNG，写字层只影响阅读；正文与落款分区，过长改短句，不缩字挤行。替换正文同步重新制票。
- **验收：**书写中、写完后分别存图，解压核对两个 PNG 的字节、尺寸、透明和内容。下载成功不等于下载正确；文件协议读取失败时先用本地服务器复测。

## 投递与同步

### 11｜测试收藏污染正式最新信

- **现象与依据：**W51 曾出现还未取信，最新信已经入册。
- **原因：**只按编号或旧 `collected: true`，将同编号旧候选的动作继承给新内容。
- **操作：**手动收藏绑定内容标记，测试使用独立 storage key。公共标记包含编号、日期、地点、标题和图片路径；覆盖同名图片需更新路径或版本参数。
- **验收：**旧存储打开最新信不提前收藏；手动入藏并刷新后保留。同编号换图、TEST 和撤回都复测，不能清空用户全部收藏来掩盖迁移问题。

### 12｜把阅读等同于收藏，把最大编号当数量

- **规则：**地图显示所有有效正式信；旧信自动入藏并已读，最新信等待手动入藏，读过不自动收藏。
- **操作：**根据有效列表计算 N，测试不参与；撤回后重算、藏信倒序。三封未藏最新时有两枚旧信，七封有六枚。
- **验收：**读最新仍 N−1，手动入藏后 N，新信到来旧 N 枚已读。[状态检查](../tests/archive-state.test.cjs) 覆盖这些场景。已手动收藏最新的浏览器显示 N 正确，不应强制重置。

### 13｜后台有新信，手机却只有三个点

- **现象与依据：**私人版 v13 前部分环境静默回退底版，后台索引仍有增量。
- **因素：**单次读取失败即回退；若读取额外依赖 MCP 写入者身份，普通浏览器未必带有相同上下文。
- **操作：**已受保护私人站点的只读接口复用外层门禁，写操作仍单独授权；同源携带凭据、每次六秒、最多三次、间隔 900/1800ms。失败显示且保留 `SYNC ERROR`，重绘不抹掉。裸公网 Worker 需自行认证，不能照搬删除额外检查。
- **验收：**同一正式入口分别测桌面、手机普通浏览器和需要支持的 App，核对请求、完整数据和页面。任一端只剩底版就继续查，不改计数或换网址伪装成功。详见[接入说明](自动投递与跨设备接入.md)。

### 14｜共享信箱被说成个人账号同步

- **已纠正表述：**各端取得同一发布索引，不表示手机手动收藏已同步到电脑；私人版与公共模板的个人动作仍按浏览器保存。
- **操作：**分别说明两条链。真正个人同步另需登录、稳定用户 ID、用户隔离数据库、内容版本和冲突策略，仅修改 storage key 不会实现。
- **验收：**另接后，手机收藏桌面刷新可见、其他账号不可见，覆盖离线和同编号换内容。没有这些证据，只报告来信列表一致；接入文档中的方案不等于已有接口。

### 15｜接口有数据，公共机器却接不上

- **性质：**本次源码核对发现的接入风险，不冒称新上线故障。
- **原因：**私人投递器使用 PNG data URL，公共 `machine.js` 当前接受资源 URL；初始化还立即建立列表、lookup 和点位，事后改全局数组不会重建它们。
- **操作：**先映射到受控同源资源，或扩展对已验证 PNG data URL 的支持；完成读桥后再初始化。不能添加程序不认识的 `feedUrl` 就声称接通。
- **验收：**实际读入一封测试信，核对地图、正文、翻面、下载和收藏；坏批次拒绝、失败可见。公共模板当前未启用此后端，需接手者实现。

### 16｜日程设好了，就以为信到了

- **原因：**源码可读、工具可见、写权限、生图、发布和网页可见是不同阶段。
- **操作：**先手动跑完整流程，再验证新云任务上下文；创建前查重。候选校验哈希/图片、读回再发布，重试保持 ID/哈希，索引写入防并发覆盖，失败按最后一封的边界回滚。
- **验收：**后台数据与索引正确，正式网页可交互，旧信仍可读；报告区分日程保存、本次运行、发布、网页验收。页面定时器不能替代网页关闭时运行的云任务。

## 部署与交付

### 17｜首页能打开，就当部署全通过

- **常见原因：**根目录错、资源相对路径错、文件协议限制，或误把静态托管当成会运行 Worker 的后端。
- **操作：**Vercel 机器根目录 `template`，Netlify 按仓库配置，Pages 机器位于 `/template/`；核对资源实际请求。增加 `worker/` 文件不会令静态托管自动运行服务。
- **验收：**部署入口走地图、出票、翻面、下载、入藏和刷新。新账户副本部署另验；配置和 CI 通过不等于已经在新账户部署成功。

### 18｜视频计数和字形不同于当前机器

- **已确认原因：**用户指定的 45 秒有声原片记录 W41，公共机器使用独立三份样例与现行规则。
- **操作：**保留原片并标明历史阶段，不为了看似一致而改原视频；当前行为以实际机器和 [行为对照](../template/USAGE.md#收信与阅读) 为准。
- **验收：**核对源文件哈希、45 秒、1080p、音轨和播放器；当前交互另测，不能由视频校验替代。

### 19｜只说“参考了”，没说谁、怎么改

- **此次缺口：**原致谢一句话，缺少各项方法的角色和随包许可，容易被误读为完全从零独创。
- **操作：**注明池又雨的概念启发，cakeni、Yan Liu、FANTASY／梵想美学的 Skill 方法，以及游目窗后加的画芯/套版/透明/验收规则。保留完整提示词、改写说明和适用许可；原分享帖链接未找回就明示。
- **验收：**README 与网页有入口，独立取出 Skill 也有来源和许可。核心提示词无“同上”或省略替代；上游 MIT 不自动覆盖所有研究图，署名不替代素材许可。见 [灵感与致谢](灵感与致谢.md)。

### 20｜文件写了、测试绿了，就说全部好了

- **区别：**文件、程序输出、部署状态、交互、下载和用户设备是不同证据。
- **操作：**每轮确定目标、保留项和验收方法，只报告实际检查过的内容；缺工具标明具体待验项，继续完成独立工作。尺寸、字段和路径不能都留给用户发现。
- **验收：**交付一个明确入口，说明改动、检查与剩余项。窄屏不是手机真机，旧候选不是新生图，公共模板不是私人后台已开源，说明写了不等于接口已运行。

## 怎样收尾

开始前确定基线、目标和保留项；出问题只修对应层。收尾保留来源、输入、画芯、数据、成品、实际检查结果、正式入口和恢复办法。

历史快照用于追溯，现行 Skill、规则、代码与使用说明用于执行。早期 W1–W11 缺少完整逐版文件，不编造每版改动；私人讨论稿中的提案也不能写成已完成能力。

六组 Skill 示例已补齐原图与完整成品；旧三组保留历史结果，新三组从本次照片转绘并检查。手机实际听感/书写体验、未追溯齐全的采样来源和配乐使用范围仍单列，不因示例补齐而标为全部验证。
