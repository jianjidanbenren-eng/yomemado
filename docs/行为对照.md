# 公开机器与已确认原机的行为对照

公开模板沿用原机前台的收信、阅读、入藏规则。样例数量与私人信箱独立；这里的三枚样例不连接私人数据。

| 项目 | 已确认的规则 | 公开模板的行为 |
|---|---|---|
| 地图 | 显示全部有效正式来信 | 三封样例显示三个点、RECEIVED 03；`testOnly: true` 不参与正式点位和最新信判断 |
| 藏信初始状态 | 旧正式来信自动入藏并显示 READ / 已读 | 三封时先有 001、002 两枚旧信；003 等待亲手入藏 |
| 最新信读过但未入藏 | 阅读与收藏分开 | 翻阅 003 后可标记读过，藏信仍只有 001、002 两枚 |
| 最新信手动入藏 | 点击「入藏」才加入藏信 | 003 入藏后，地图仍三个点，藏信变成三枚且均已读 |
| 后续新信 | 新信抵达后，旧正式来信自动归档 | 加入 004 后，旧 001–003 自动入藏并已读，004 等待手动入藏；七封时对应六枚旧信已读 |
| 藏信顺序与本地记录 | 新信在前，手动选择绑定当前内容 | 按编号倒序；刷新保留本浏览器的手动入藏记录；标记包含编号、日期、地点、标题和图片路径，旧 `collected: true` 不会自动替最新信入藏 |
| W32 写字 | 翻面后两段正文逐字出现，最后出现落款 | 等待 770ms；第一段 2180ms，间隔 430ms，第二段 2060ms；文字和钢笔声由同一套段落回调触发 |
| 静音与中断 | 静音保留写字；翻回、合上或换信取消当前书写 | 关闭机音后文字继续写，钢笔声停止；再次翻面从头写，不串入上一封的字或声音 |
| 机音与机械反馈 | 使用原音效、出票轻震和入藏提示 | 八个采样与原 V3 出票程序保留；音效提前准备，原 W38/W41 机身及藏信布局保留 |
| 存图 | 保存完整高清正反面，不保存动画半成品 | 无论正在写到哪一段，ZIP 都使用现有完整 736×1040 RGBA PNG，不重绘、不截取屏幕 |

页面的「制作、素材来源与更换说明」中也有三点／两枚旧信／最新信手动入藏的简明说明。已经手动入藏过最新一枚的浏览器会显示三枚，这是同一条规则的后续状态，不会强行清空记录。

## 公开模板的明确差异

- 公开版默认宋体，可换字体；逐字显示的正文来自 `letters.js`。原始 PNG 保留为纸面和下载成品，修改页面文字或字体不会自动重绘下载图片，替换内容时应同步重新制票。
- 来信和图片来自仓库，收藏保存在当前浏览器。它不接入私人账号、私人 API、个人提醒或自动投递后台；跨设备账户同步与自动采风需要部署者另行配置。
- 浏览器与窄屏排版检查不代替手机真机的实际听感验收。

本次验证：14 项 Node 检查、20 项 Python 检查通过；桌面浏览器确认正文逐字推进、静音仍写、读后未入藏仍为两枚、手动入藏并刷新后为三枚。360 像素窄屏的正文、落款与操作按钮已查看，无横向溢出。
