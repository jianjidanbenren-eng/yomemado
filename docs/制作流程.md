# 制作一封来信

这是一份可复用的工序说明。私人版的 W48 母版与 W51 网站并未包含在公开仓库中。

## 1. 采风

选一个真实地点与具体主题，保存完整地名、地区、经纬度的依据、资料链接和核查日期。区分「资料证实」与「画面演绎」。若用照片转绘，确认照片的使用权；若自主创作，不能把想象视角说成真实照片。

## 2. 画芯

让图像工具只交付一幅竖向、无文字的插画。目标画幅适配 624:723 的画芯槽。不要让模型生成地名、编号、邮戳、边框或齿孔。照片模式保留主要建筑形态、相对位置与光线；自主采风模式依据核实的地理特征创作，并记录哪些画面细节是演绎。

## 3. 套版与写信

由自有或获准使用的母版负责纸色、固定字、边框和齿孔。动态层只替换编号、地区短名、画内标题、副标题、中央画芯、底部恰好两行的标题。完整地名保存在事实数据里；短名只供印刷。背面短笺要能独立读懂，日期以实际寄出时间为准。

正反面各导出 **736 × 1040 RGBA PNG**，共享同一齿孔 Alpha。不要把黑色或棋盘格背景烘进透明区域。用 `tools/check_stamp.py` 检查基本像素条件，再在浅色和深色底上肉眼检查边缘、文字溢出与背面排版。

## 4. 投递与验收

把画芯、两面 PNG、完整数据与来源记录保存在私有存储。投递前查编号、核对哈希与测试身份；发布后查索引，并亲自打开目标站点确认新红点、完整地点、出票、翻面、下载和藏信状态。失败时撤回测试件，复查旧信仍能阅读。**后台显示“发布”不等于网页已验收。**

后端接入、定时任务和跨设备读桥的配置单与逐步操作见[自动投递与跨设备接入](自动投递与跨设备接入.md)，其中包含接口参数、失败恢复和给接手小机的提示词。

## 藏信的不变量

设有效信件编号按旧到新为 `001 … N`。地图展示全部有效信；未手动入藏最新 `N` 时，藏信只显示此前有效信，从新到旧排列。对 `N` 点击入藏后才把它放到最上面。新 `N+1` 抵达后，先前的 `N` 成为已归档信件，`N+1` 仍等待亲自入藏。撤回测试件后重算，旧浏览器的收藏标记不能替当前信自动入藏。

例如 `005` 到达而没有被点击时，地图有五封，藏信是 `004 → 003 → 002 → 001` 四封；下一封到达则先显示 `005 → … → 001` 五封。这个例子描述规则，不提供私人信件内容。
