# 游目窗从哪里来｜灵感、Skill 参考与改写

游目窗不是从零独立发明所有方法。我们借鉴其他伙伴公开的想法与 Skill，再围绕“从世界收到一封信”改成现在的机器、邮票生产链与收信规则。这里说明谁提供了什么启发、哪些地方经过改写，以及哪些出处仍待找回。

## 1. 概念的起点

感谢 **[池又雨 / Yinglianchun](https://github.com/Yinglianchun)** 分享的“世界之窗”与外部唤醒思路：让 AI 主动接触世界，把见闻带回共同对话。游目窗沿此方向发展出地图点亮、机械出票、翻面读信、亲手入藏的形式。

相关公开项目：[SameWindow](https://github.com/Yinglianchun/SameWindow) 展示了人与 AI 共享浏览窗口的方向；[ChatGPT Context Bridge](https://github.com/Yinglianchun/chatgpt-context-bridge) 提供外部请求、Work 与 Site MCP 的相关教程。它们在此列为灵感与相关方法阅读，不表示游目窗直接使用了其代码，也不表示作者为本项目背书。

最初看到的“世界之窗”分享帖原始链接尚未从历史记录中找回。当前以作者及已核对的公开仓库署名，不将另一个教程链接冒称为原帖。SameWindow 当前使用自定义的非商业相同方式共享许可，不能被当作本仓库 MIT 内容再分发；本项目没有打包其代码。

现有历史致谢已列出三项参考，本次核对原仓库说明后补写上述关系。没有早期逐句改写记录的部分不编造映射；“借鉴与改写”不等同于断言三个程序全部直接 fork。

独立分发 Skill 时也能读到的作者、改写与许可记录在 [Skill 来源](../skills/yomemado-stamp-maker/references/sources.md)。三份上游 MIT 原文已随 Skill 保存，后续转发请一并保留。上游示例图和第三方研究图按各自条款处理，没有因为 Skill 文本使用 MIT 就自动成为可自由搬运的素材。

## 3. 我们在此基础上形成了什么

| 游目窗迭代 | 形成的具体规则 |
| --- | --- |
| 照片转绘／自主采风双模式 | 照片负责构图事实，资料负责自主模式的已核实事实；风格参考只负责视觉语言 |
| 画芯与印刷分工 | 模型只做无字画芯，固定程序生成文字、系列标识、框纸与透明齿孔 |
| 统一母版 | 624×723 画芯、736×1040 正反面；两面 Alpha 相同，固定区域保持一致 |
| 全称与简称分层 | 邮票印刷用准确短名，地图、藏信和资料保留全名；底部地名固定两行 |
| 机器阅读过程 | 地图选点、出票、翻面、两段逐字写信、原版声音、下载和藏信 |
| 来信与个人动作分层 | 旧信自动入藏且已读；最新信等待手动入藏；各设备共享信箱与个人状态同步分开 |
| 交付验收 | 实际运行脚本、看透明边缘、检查下载、在正式入口读回；不把生成文件等同于完成 |

W42–W48 的私人原规范是公共 Skill 的直接整理来源，私人称呼、素材路径和已过时的发行状态已替换为公开包实际存在的文件和独立样例。三份完整画芯提示词保留；本次补充的工作流提示词明确标为新增。详见 [完整提示词](../skills/yomemado-stamp-maker/references/prompts.md) 与 [踩坑指南](踩坑复盘.md)。
