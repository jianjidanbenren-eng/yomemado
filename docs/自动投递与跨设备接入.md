# 接入 Site、插件、定时任务与邮箱提醒

**当前公开版是静态网页，不带自动采风、自动投递、邮箱提醒或账户同步后端。** 本页是接手入口与实现约定；不会因复制仓库或安装 Skill 自动启用这些能力。

| 你需要什么 | 连接到哪里 | 做到哪里就停 |
| --- | --- | --- |
| 手动放信、玩机器 | [使用说明](../template/USAGE.md) | 部署静态网页，无需 Site 插件或定时任务 |
| 定期提醒自己来看看 | ChatGPT 的定时任务与通知设置 | 提醒附网页链接，不生成或发布新信，无需 Site 写入插件 |
| 到点采风、制票、投递，再通知 | 自己的后端与存储、可在云端调用的写入连接、定时任务 | 手动链路和新的云任务均实际跑通，再保存日程 |

默认机器行为只在[收信与阅读](../template/USAGE.md#收信与阅读)维护；外形、音效、字体、配乐等修改入口只在[替换内容](../template/USAGE.md#替换内容)维护。

## 快速交给小机

把仓库地址与这段话交给自己的小机，填写已有信息即可；缺少的技术配置由小机先检查环境，不要求使用者自己翻完全部文件。

```text
请接手这个游目窗项目，先读 README，再按需要读取 template/USAGE.md、
本接入说明和 skills/yomemado-stamp-maker/SKILL.md；每项规则使用其唯一来源。
目标：[我的现有网页/Site 链接与源码位置；尚未部署则写希望使用的平台]
方式：[手动部署 / 只定时提醒 / 定时采风制票并投递后提醒]
日程：[频率、时间、IANA 时区，例如每周二和周五10:00，Asia/Shanghai]
通知：[优先邮箱；结果附我的固定网页直链]
样式：[沿用默认 / 我的外形、音效、字体、配乐及邮票设计要求]

已有站点就沿用原 Site 和访问范围。外形与声音可以按明确要求修改；
只接后端时沿用我已经选定的样式，不顺手重做。未知地点与坐标不编造。
手动部署只交付可玩的模板；只提醒就配置提醒，不增加制票或写入。
自动投递时按本页顺序实现自己的后端、存储、工具连接和前端读桥，
先验证一封测试信与新的云任务连接，再查重、保存日程并核对下次时间。
优先引导开启账户可用的任务邮件通知，实际试收；邮件选项不可用时明确说明。
个人阅读/收藏先沿用浏览器本地，只有我明确需要时另做账户同步。
最后给出固定入口、工具连接、日程、邮件实收和未完成项的真实状态。
不要连接作者的私人 Site、信箱、任务或凭据，也不把静态模板说成自动接通。
```

## 按这个顺序连接

### 1. 准备自己的运行位置

手动网页按使用说明部署即可。自动投递另需持久存储和可受保护写入的后端；GitHub Pages 只托管静态内容，不能直接运行 Worker。可把后端放在 ChatGPT Sites 或自己支持服务端的平台，保留现有页面时实现正确的前后端连接。

制票 Skill、源文件和图像工具须在未来任务的执行环境可用。网页／Cloud 任务不保留本机文件夹；把必要材料放在可访问的仓库、上传文件或连接的服务。依赖本机文件或本机 Skill 的桌面任务，需要电脑和应用持续运行。

### 2. 发布后端，再连接 Site 插件

使用 Sites 时，按当次 Sites skill 实现自己的存储、读写路由和权限；需要 MCP 工具时声明 `capabilities: ["mcp"]` 并提供 `POST /mcp`，由所有者发布。复用 Sites 为这台 Site 生成的插件，不另建一份相同连接。

在 Work 中检查该插件工具是否已可用；若需要安装／连接，进入 **Plugins → Personal → Created by you** 找到对应插件，按实际界面完成 Install／Connect。接手小机也可读取 `get_site(include_mcp_connection: true)` 返回的插件信息，引导安装；不要猜插件 ID。先调用只读状态工具，再验证写入权限。

插件让小机调用工具，定时任务决定何时运行，邮件由通知渠道送达。自动更新也可使用其他已验证的云端写入连接；只提醒或手动模板不必先建 Site 插件。

### 3. 手动走通一封信

按[制票 Skill](../skills/yomemado-stamp-maker/SKILL.md)完成双面 PNG，随后暂存 → 校验 → 读回 → 发布 → 固定正式网页检查。图片、内容、地图和下载均对应同一封信；测试件不占正式发行，也不污染收藏。

确认新的云任务上下文也能取得源材料、生成能力及已授权写入连接，并读回持久化结果。仅在当前聊天能调用、仅有预览数据或只保存了日程，都不算接通。

### 4. 保存或复用定时任务

在同一 Work 会话让小机按已选方式和日程创建任务；说明频率、具体时间、时区及结果返回位置。先查询匹配任务，已有任务就更新，保留暂停状态，不重复创建。

若用 Sites 的关联日程，小机先读取该 Site 的 `automations`：缺失或为 null 时先恢复查询，不能当作没有任务；可用时复用匹配项，新增按 Sites 的日程入口办理。普通提醒使用 ChatGPT 定时任务即可。

创建后到 **Scheduled／定时任务** 核对指令、启用状态、时区和下一次运行；在这里查看运行记录、改时间或暂停。自动投递任务应在发布并读回成功后返回固定网页链接，失败则说明停在哪一步。任务结果返回会话／Scheduled，不是网页自身弹出通知。

### 5. 优先开启邮箱提醒

打开 **ChatGPT 设置 → 通知**，找到任务相关通知；若账户提供电子邮件渠道，开启它，并按实际界面完成需要的权限设置。账号、套餐和工作区可能影响可用渠道；仓库不能替使用者开启全局通知。

试运行一次任务，分别检查任务结果和邮件实收，必要时查看垃圾邮件。只有收到邮件才标记邮箱提醒通过；日程保存、任务完成和邮件送达分开记录。平台通知不是可任意指定收件人的邮件接口；若账户没有邮件选项，或需要发到另外指定的地址，按使用者选定的邮件服务另行配置，并说明尚未接通的部分。

### 6. 留下一个明确的交付结果

记录自己的正式入口、后端／插件连接状态、日程与下次时间，以及邮件实收结果。自动投递还需在同一入口验证桌面和手机普通浏览器能读到同一批信，并走取信、翻面、下载与入藏；缺少真机就保留待验证，不用窄屏模拟替代。定时任务首次运行后再复查一次，避免把单次手动成功当成长期稳定。

## 小机实现时查这里

以下是原私人实现提炼出的接口约定，**后端代码和在线服务没有随公开仓库提供**。接手者需要实现或映射到自己的服务；不要把下列名称直接塞进 `config.js`。改过邮票规格时，前后端图片校验也按新规范一起适配。

### 数据与投递合同

- 内容字段以 `template/letters.js` 为网页结构、Skill JSON 为制作资料，合并时补齐地图和图片地址；正式 ID 唯一、测试件标记 `testOnly: true`，实际寄出日期与未知坐标分别保存。
- 原接口采用内嵌 PNG data URL，默认要求两面 736×1040、8-bit RGBA、非交错且 Alpha 一致；公开 `machine.js` 只接受资源 URL。接入时把图写成受控同源资源并映射，或仅放行校验过的 PNG data URL，不能直接复制原 JSON。

| 顺序 | 原工具约定 | 实现职责 |
| --- | --- | --- |
| 1 | `get_delivery_status()` | 有效编号、连接状态、写入者权限 |
| 2 | `upload_letter_chunk(id,index,total,dataBase64)` | 只暂存，不发布 |
| 3 | `finalize_letter_candidate(id,total,sha256)` | 拼接、哈希和图片／字段校验 |
| 4 | `get_letter_candidate(id)` | 读回哈希、大小、地点和图片摘要 |
| 5 | `publish_letter_candidate(id,sha256)` | 发布正文，最后更新有效索引 |
| 6 | 状态工具与正式网页 | 索引、完整内容和页面一致 |
| 撤回 | `rollback_last_letter(id,sha256)` | 仅撤回最后发布的同一候选 |

按最终 UTF-8 JSON **字节**计算 SHA-256，再按字节分块并分别 Base64；索引从 0 开始。原实现每块最多240,000个 Base64 字符、最多64块、候选最多10,000,000字节，一次最多读50条增量；超出要另做分页。重试保留同一 ID／哈希，重复发布幂等；索引串行或原子更新。替换暂存候选需核对旧哈希并提供 `replaceSha256`；在线同编号修正先备份并设计恢复，后续已有别的信时不自动撤回旧信。

### 在线读桥与所有者权限

持久存储可用 R2（示例绑定 `BUCKET`）；原实现写入身份配置名为 `WRITER_EMAIL`，由部署者在服务端填写自己的值。只读接口示例为同源 `GET /api/private/letters`，成功返回 `{"letters":[完整增量来信]}`，不重复底版 ID；没有增量才返回空数组。

`worker/index.ts` 路由与 `worker/delivery.ts` 读取权限保持一致：对于外层平台已经验证所有者的私人站点，普通浏览器读信不再额外索要 MCP 写入头；上传、发布和撤回仍检查写权限。自建公网服务须验证自己的会话，不能信任浏览器自填的 `oai-authenticated-user-*` 头。私人响应使用 `Cache-Control: private, no-store`，校验失败返回明确错误，不伪装成空信箱。

前端先读底版，再异步读取完整增量，校验全批后一次合并，最后初始化 `machine.js`；它初始化后的 `letters`、`lookup` 和点位不会因改全局数组自动重建。原 v13 用 `credentials: 'include'`、`cache: 'no-store'`，每次6秒超时、最多3次，重试等待900/1800ms；最终失败保留底版和持续可见的 `SYNC ERROR`。诊断记状态、次数与失败阶段，不记私人正文或凭据。

当前模板没有读桥或 `feedUrl` 开关。新信默认在打开／刷新时读取；需要恢复焦点或定时刷新时另实现，并处理正在出票／书写的状态。页面计时器不能代替网页关闭后的云任务。故障定位见[踩坑指南](踩坑复盘.md#投递与同步)。

### 可选个人状态同步

同一发布索引让设备读到相同来信；阅读／手动入藏默认仍在各浏览器保存。真正同步另需登录、服务端稳定用户 ID、按用户隔离的状态表及版本冲突处理，尚未包含在私人版或公开模板中。

需要时按 `(site_id,user_id,letter_id,letter_version)` 保存阅读和手动收藏，版本绑定内容／图片；可实现自己的 `GET/PATCH /api/me/letter-state`，检查会话与用户归属。第一版可合并有效 true，旧 false 不覆盖；支持取消时再加删除标记和冲突策略。本地迁移需使用者选择，离线状态明确标待同步。按[收信规则](../template/USAGE.md#收信与阅读)派生旧信展示，不批量写入“真实已读”。用同账号两端、另一个账号、离线重连与同编号换内容验收。
